# PageIndex — 目次をたどって、根拠に届く

## 制作契約

- 対象：AIにPDFを読ませることに関心がある一般視聴者。RAGは画面で「資料を探して答える」と補足。
- 尺：日本語音声の実測に合わせた約60〜80秒、9:16、1080×1920、30fps。
- 核心：文章の類似度による検索とは異なり、文書構造と章の説明を手がかりにAIが読む場所を選ぶ。
- 入口：架空の決算資料で「利益が減った理由」を聞くと、「利益を伸ばす目標」だけでは回答にならない。
- 見せる関係：質問→文書のツリー→業績→費用→本文p.42→根拠付き回答。
- 誤解防止：一般的なベクトル検索が必ず失敗するとはしない。PageIndexの実測デモではなく、仕組みの模式図。引用・推論の正確さは別途確認が必要。
- 人気を実証した企画ではない。今回は利用者指定の題材の制作。
- 比較するのは代表的な検索の発想。RAG全体をベクトル検索だけに限定しない。
- 索引生成全体をLLMだけで行うとは言わない。現在のFlashはレイアウトから基本構造を抽出し、要約・最適化にLLMを使う。
- 費用・速度・精度の優位や98.7%等のベンチマーク数値は、この動画では扱わない。

## Director packet

一つのScene、固定カメラ。PDFから断片へ、その断片の意味を保って章ノードへ変形する。
PDF、質問、選ばれた経路、到達した本文をつなぎ、定義だけを並べる動画にしない。
scene familyは比較からツリー探索へ進むprogressive disclosure。
operatorsはstable scaffold、attention baton、route packet、commit hold next。
ツリーの点を移動させる一回のplayが、読む対象を一段選ぶ意味に対応する。

### 対象と意味の台帳

|id|対象|色|継続|
|---|---|---|---|
|obj_question|利益が減った理由は？|白|冒頭から回答まで上部に固定|
|obj_report|架空の決算資料|青灰|PDF→ツリーのルート|
|obj_chunks|三つの文章断片|青灰／橙|断片→対応する章へ変形|
|obj_policy|目標のみの記述|橙|経営方針の枝として残る|
|obj_tree|章・節の階層|青灰|中盤以降の記憶の足場|
|obj_cursor|AIが選ぶ読む場所|シアン|ルートから本文まで同じ点が移動|
|obj_cost_page|費用の分析p.42|シアン|葉から本文へ拡大|
|obj_answer|物流費増加→利益減少、根拠p.42|緑|本文から回答へ転写|

### 画面と衝突境界

frameはx=-4.5..4.5、y=-8..8。右端0.7、上下0.7以上の余白。
ブランド小見出しy=7.0、見出しy=5.8、質問y=4.15。
main stageはx=-3.8..3.3、y=-3.8..3.25、字幕はy=-5.05、出典・模式図表記はy=-6.8。
主要な日本語は32〜48pt、ノードは25pt以上。木は幅7.0以内。
ノード・本文・回答は別の領域を使い、字幕と重ねない。枝の接続先は動かす前に確定する。
同時の焦点は一つ。文脈は薄く残し、選択した経路だけシアンにする。
全盤面のclearは禁止。終盤で木を縮めて上へ置くのは、本文と回答の空間確保のため。

### beat graph / shot・focus・pacing

音声の終端まで余白を実測。表のplayは主動作の予定、残りは読解用holdと焦点の小さな変化に使う。

|beat / shot|音声の役割|焦点と動作|play秒|hold目安|着地|
|---|---|---|---|---|---|
|0 / shot_problem|探す場所がずれる問題|PDFから質問と経営方針のページへ|2.4|1.0|回答に必要なのは何か|
|1 / shot_chunks|よくあるRAG|PDFの断片が別々のカードになる|2.6|1.0|意味が近い断片を探す|
|2 / shot_mismatch|似ている≠答え|目標のカードを選択し、質問との不一致を示す|2.3|1.5|目標は減益理由ではない|
|3 / shot_structure|ツリーを作る|同じ章の意味を持つカードをツリーの枝へ|3.0|1.0|階層が索引になる|
|4 / shot_traverse|読む場所を選ぶ|同じ点が決算資料→業績→費用へ順に進む|3.5|1.2|章の説明を使う選択|
|5 / shot_evidence|本文を根拠にする|費用の葉からp.42本文が開き、記述が回答へ移る|3.5|1.8|回答と根拠の対応|
|6 / shot_principle|方式を要約|経路を再強調し、ベクトルDB不要の特徴を短く表示|2.4|1.4|構造をたどる検索|
|7 / shot_limits|条件を残す|同じ足場の下に精度・時間・費用の確認項目|2.0|1.2|万能な精度保証ではない|
|8 / shot_payoff|核心を定着|ツリー→本文→根拠付き回答を残す|1.6|最終2.5秒追加|目次から根拠へ|

固定カメラのため全beatでcamera=locked。主要shot名をコードのnext_sectionに記録。
ラベル・色の同一性はTransform/TransformFromCopyで保持。
図は全て新規作図、実在企業の決算数値やPageIndexを実行した結果ではない。

## Pre-code gate

題材保持、問いと回答、文書構造と経路、固定カメラ、画面領域、焦点、保持時間、
模式図の注記、上流ソースの参照、最終画面の関係を定義済み。
APIキーを使うPageIndexの実行デモ、ランキング実験、外部LLM評価はスコープに含めない。
ドラフトで断片→ツリーの移行と探索を確認し、最終1080pのフレームを再確認する。

Manim grounding：Scene / Text / VGroup / RoundedRectangle / Line / Dot / Arrow、
TransformFromCopyとReplacementTransform。式のsymbolは使わず、PageIndexの名称とページ番号p.42を保持する。
source anchors：beat表の9つのshot名をnext_sectionに、上記対象idを変数またはコメントに置く。
acceptance：質問→経路→本文→回答がつながること、本文と字幕が衝突しないこと、
出典・模式図・音声クレジットが残ること。修正時もbeat順、対象の色、経路、最後の根拠表示を保持する。
