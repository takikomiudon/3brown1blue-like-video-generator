# 対象の変化で説明するための制作契約

v2.0.0 / 2026-10-19。
扱う題材や映像ツールにかかわらず、**同じ対象の変化を追うと関係や仕組みが分かる**ことを求める。
動作の種類・対象・レイアウトは題材から決める。

## 設計から完成まで

1. 伝える関係を一つ決める。
2. その関係を担う対象を選び、変化前・途中・変化後を設計する。
3. 対象の変化が、どの説明に対応するかを書く。
4. 中心部分の5〜10秒を動く試作として描画する。
5. 実際の動画または連続フレームで、中間状態と意味の対応を確認する。
6. 合格した手法を全編に展開し、音声の実測時刻に結びつける。
7. 最終MP4を機械検査し、説明区間ごとに意味を確認して記録する。

動作は、位置・量・形・接続・集合・場の状態等の変化として表せる。
一定の描画方法を全ての題材に適用する必要はない。
読み取ってほしい結果には保持時間を設け、その対象・理由・時刻を記録する。

## 動作計画

`motion-plan.json` の `roi` は `[x, y, width, height]`、左上原点、0〜1の正規化座標。
説明対象を含む主図の領域を指定し、補助表示は別の領域に置く。
フレームの比率や題材ごとに座標を決め、例の値を固定値として流用しない。

`beats` は映像の最初から最後まで、重複や欠落なく並べる。

- `kind: mechanism`：説明対象の変化が理解を担う区間。object/before/action/after/meaningを全て具体化する。
- `kind: context`：前提や問いを提示する区間。
- `kind: summary`：理解した関係をまとめる区間。
- `holds`：読むための保持をstart/end/kind/reasonで指定。kindは`read`または映像末尾の`final`。

[JSONのひな型](../templates/motion-plan.example.json) を、作品の対象と実測時刻で埋める。
ひな型の `roi: null` は、主図の実際の座標4値に置き換えるまで検査を通さない。
上位の `plan.md` には読み取る順序・焦点・画面配置・合格条件を記録する。

## 機械検査が確認すること

```bash
python3 /actual/skill/path/scripts/audit_motion.py \
  outputs/final.mp4 --plan motion-plan.json --output outputs/motion-audit.json
```

必要な環境はPython標準ライブラリ、ffmpeg、ffprobe。
検査は主図を160px幅・10fpsの輝度画像として読み、隣接時刻の差を測る。
基準は制作時の見落としを検出するための初期値で、作品の魅力や視聴維持率を保証する統計法則ではない。

- 輝度差16以上の画素が主図の0.05%以上ある時刻を変化として数える。
- mechanism区間では、保持を除く時刻の12%以上に変化があり、0.3秒以上連続して中間状態が確認できること。
- 説明のための区間が、保持を除く全体の半分以上を占めること。
- 4秒を超える変化のない区間には、読む対象と理由を伴う保持の宣言が必要。
- 読解用の保持は一回4秒以内、末尾の保持は6秒以内、保持の合計は全尺の40%以内。

これらを満たしても、動作の意味は次のレビューで確認する。
`--mechanical-only` は検査器の診断用。完成判定は通常モードで `status: PASS` を得る。

## 意味のレビュー

機械検査で得た `video_sha256` を使い、実際に確認した最終ファイルについて記録する。
各mechanism区間で、同じ対象の途中状態が追える3点以上の時刻を残す。
対象、観察した変化、その変化が伝える意味を、それぞれ具体的に書く。

```json
{
  "video_sha256": "確認した最終MP4のSHA-256",
  "method": "frame_sequence",
  "checks": [
    {
      "beat_id": "mechanism",
      "observed_object": "実際に追跡した対象",
      "observed_change": "描画結果で確認した状態の変化",
      "meaning": "その変化で読み取れる関係や仕組み",
      "evidence_times": [1.0, 1.3, 1.6],
      "explains_mechanism": true
    }
  ]
}
```

`method` は `video` または `frame_sequence`。
`checks` はmechanismの全区間を一度ずつ扱う。
意味を確認できない区間は `explains_mechanism: false` として、対象や動作を修正する。
レビュー記録は実際に観察してから書く。

```bash
python3 /actual/skill/path/scripts/audit_motion.py \
  outputs/final.mp4 --plan motion-plan.json --review motion-review.json \
  --output outputs/motion-audit.json
```

通常モードの終了コード：0は両方の検査が合格、1は要修正、2は意味のレビュー待ち。
画像差から意味そのものを自動判定するツールではない。
宣言した領域やレビューの正しさは、実際の描画結果に照らして確認する。
修正後は新しい最終MP4に対して検査・レビューを行い、結果とソースを保存する。

## スキル自体を検証する

```bash
python3 /actual/skill/path/scripts/test_audit_motion.py
```

検証用の対象を異なる時刻列と領域で描画し、検出範囲、連続性、レビューと映像の一致、終了コードを検証する。
これは検査器の回帰検証であり、別セッションの生成エージェントの振る舞いまで保証する実験ではない。
