# 保存・復元・動画の受け渡し

## 実際に起きた消失

最初のスキルと調査文書は作業環境に作ったが、GitHubへ保存していなかった。
環境が切り替わると初期READMEのチェックアウトになり、未コミットの文書・コード・動画を回収できなかった。
そのため「導入済み」という説明だけでは継続利用を保証できなかった。

2026-10-19に完成動画・スキル・調査文書を `main` へ統合した。現在の保存先と作業先はmain。
以前の作業ブランチは履歴として残る。環境の公開スナップショットとGitHub保存は別。

## 保存の最低条件

1. `git status`、変更の一覧、必要な生成物を確認する。
2. コード、原稿、README、SKILL、参照資料、出典、検証結果をコミットする。
3. ユーザーに渡す必要のあるMP4を無視対象だけに置かない。今回の5.3MB/2.5MBのMP4はGit管理している。
4. 許可された作業ブランチへpushし、リモートのSHAを確認する。
5. 別のクローンで必要なファイルが取得できることを確認する。

既存の未コミット変更、ローカルだけのコミット、認証情報を勝手に消したり公開したりしない。

## リンクの作り方

クラウドのローカルパスは、そのままユーザーが受け取れるファイルURLではない。
この公開リポジトリでは、保存したコミットを指定したHTTPS URLを利用した。

```text
https://raw.githubusercontent.com/takikomiudon/3brown1blue-like-video-generator/<commit>/shorts/decay-heat/outputs/decay-heat-short-ja.mp4
```

現行動画の保存コミットは `a0bb4c5a113e8b020e371bc26cdab09f09215637`。
GitHubのファイルページから **Download raw file** でも取得できる。
raw配信はapplication/octet-streamになる場合があるため、インライン再生を保証せず「ダウンロード」と案内する。

## 受け渡し前の実検査

- 確定URLをHTTP GETして、200と期待サイズを確認。
- 再ダウンロードしたバイト列のSHA-256が、リポジトリ内の出力と一致することを確認。
- ffprobe、全編デコード等は最終ファイルに対して実施する。
- プレビュー用の小さな画像を見たことと、音声・動きの全編視聴は区別して報告。
- 利用者のチャットからのクリック・端末での再生をこちらで確認したとは言わない。

## 復元前に確認すること

ファイルがない場合は、まずリモートのmainを確認する。利用者の作業を上書きしない。

```bash
git ls-remote origin refs/heads/main
git fetch origin main
# 作業ツリーとローカルコミットを確認してから、必要に応じてブランチを切り替える。
```

今回の復元後は `python3 scripts/verify_knowledge.py` で、文書・スキルのハッシュ・完成動画の存在を確認できる。
