# 品質向上のための既存技術・スキル調査

2026-10-16の調査を会話から復元。依頼は「今の品質を1として100を目指すための技術を探す。独自の思いつきより、誰かが築いたノウハウを優先」。
100倍は目標の強さであり、測定済みの倍率・達成済みの結果ではない。

## 1. 演出をコードより先に決める

Manim Video Labのdirector packetには次の設計がある。

- 中心の理解と最初の具体的な問い。
- 対象・記号の台帳：名前、意味、色、画面領域、残る期間。
- 台詞ごとの段階：視線の中心、動きの役割、何を残すか。
- 図、式、字幕、前の結論を置く領域。
- カメラの目的、動かす時間、元に戻る条件。
- 変化した後に読む時間と、最終的に理解できる一枚。

原子力動画に適用できる既存の型：

|型|使いどころ|
|---|---|
|Simulation Dashboard|中性子・数値・履歴を同じ状態変数から更新する。|
|Algorithm / Pipeline Flow|経路を示し、現在動いている対象だけに注意を向ける。水と熱を混同しない。|
|Before / After Evidence|同じ初期条件・尺度で k<1 / k=1 / k>1 を比較。|
|3D Reveal With Protected 2D Meaning|断面で理解できない奥行きがある場合にだけ立体化し、字幕を固定する。|

注意：同スキルの「1〜3秒で変化」「4秒以上静止させない」等は作者の推奨。視聴維持効果の独立検証や分析データを今回確認したわけではない。理解に必要な静止を削る絶対ルールにしない。

## 2. 本人のコードで確認できる動き

3b1b/videosの `_2024/transformers/attention.py` を確認した。
調査時の870〜890行付近は現在の列以外の減光、920〜930行付近はカメラ・矢印・変換の同時実行、934〜949行付近は同じ枠による注目対象の移動、956行付近は全体への復帰。
行番号はその時点のもので、現在のHEADで同じとは限らない。

READMEのWorkflowには、ManimGLの `-se` と `checkpoint_paste()` によって短い区間を繰り返し調整する方法がある。
全編を毎回生成するより先に、短い場面を磨く作業設計の参考になる。

ManimライブラリのMITと、3b1b/videosの作品コードのCC BY-NC-SA 4.0は別。本人の場面コードをそのまま本作に組み込んでいない。

## 3. 自然な音声と同期を別々に改善する

|候補|資料で確認した特徴|未確認・制約|
|---|---|---|
|VOICEVOX ENGINE|audio_query、synthesis、話速とアクセント調整|話者ごとの条件を確認する。実際のショートは青山龍星ノーマル。|
|Style-Bert-VITS2|日本語向け、発話スタイル、CPU推論、台詞エディター|モデル別条件、取得先、メモリ・速度、試聴が必要。今回は生成していない。|
|クラウド音声|Manim VoiceoverにGemini、Azure等の接続例|認証、料金、通信先、日本語の試聴が必要。今回は呼び出していない。|
|HTS Mei|API不要で当初の環境で再現可能|自然さ・抑揚の限界。初回の比較用ベースライン。|

SBV2の `docs/TERMS_OF_USE.md` で、コードのライセンスとデフォルト音声モデルの条件が別であることを確認。

同期の方法：

1. Manim Voiceoverのブックマーク：指定した語に合わせて動きを始める既存機能。
2. WhisperXの強制アラインメント：READMEとalignment.pyで、日本語モデルと空白区切りを使わない処理を確認。専門語・数式・辞書にない文字は確認が必要。実行はしていない。
3. 現行作：VOICEVOXのクエリのモーラ時間から「押します」「崩壊熱」の位置を求める。これは全語を強制アラインメントした結果ではない。

技術的に同時刻にすることと、理解できる保持時間を取ることは別。

## 5. 全自動生成の先行事例から借りるもの

### TheoremExplainAgent

公式リポジトリで、場面目的・前場面との関係・配置を分ける計画プロンプトと、以下の1〜5点の評価軸を確認した。

- 台本：正確さと深さ、論理の流れ。
- 静止画：内容との関連、要素の配置。
- 動画：スタイルの一貫性、滑らかさ。

論文プロジェクトとしてのREADMEは読んだが、論文PDFそのものは今回取得していない。外部LLMによる採点も実行していない。
高い自己採点を、人による理解・満足の証明にしない。音声の自然さは別途試聴する。

### Math-To-Manim

READMEと公開済みcontact sheetを取得し、対象・図と式の対応・字幕・場面構成を確認。
実際の公開画像には文字が薄い箇所もあり、宣伝文だけで満点扱いしないという判断になった。
全編の音声・動きは未視聴。掲載された数学上の新しい主張を独立に検証しておらず、原子力の科学資料には使わない。
借りるのは、完成物、場面ソース、レビュー画像、ハッシュ、検証結果を一緒に残す方法。

## 6. その他の候補と、実行しなかったこと

- Motion Canvas：公式READMEが説明用ベクトルアニメーションと音声同期を明示。TypeScript中心なら候補。今回はPython資産とManim向けスキルを優先。
- Blender：実行ファイルは環境にあったが、原子炉の具体的な作例・スキルの調査と実装はしていない。3D化だけで改善すると判断しない。
- 生成映像：中心の科学図に使う根拠は集めていない。記号・流路・保存則を検査できるコードで描く方針。
- クラウド音声・外部モデル評価のAPI利用、音声候補同士の試聴比較は未実施。
